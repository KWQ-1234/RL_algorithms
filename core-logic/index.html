RL 算法的核心逻辑

在模型自己的输出上，按奖励重新加权，每次只挪一小步。

依据：核对过的约 100 篇论文与技术报告，加上推导。我没有跑过大规模 RL 训练，下面的判断不是一手实验经验。

问 1 · RL 算法的核心逻辑是什么

三层：目标、目标解、逼近方式

第一层在优化什么

$$J(\theta)=\mathbb{E}_{x\sim D,\;y\sim\pi_\theta(\cdot|x)}\big[R(x,y)\big]$$

它和监督学习有两个本质区别：

  1. 数据分布依赖于参数本身。样本 $y$ 由 $\pi_\theta$ 生成，参数一变，数据也变。
  2. 奖励是黑箱。$R$ 对 $y$ 不可导，梯度只能借助 log-derivative trick 求：
$$\nabla J=\mathbb{E}\big[R(x,y)\,\nabla\log\pi_\theta(y|x)\big]$$

这就是 REINFORCE。换个角度看，它是在自己采出的样本上做加权 SFT，权重是奖励。所有 RL 算法都从这个式子出发。

第二层目标解是什么样

加上“不要偏离参考模型太远”的约束：

$$\max_\pi\;\mathbb{E}_\pi[R]-\beta\,\mathrm{KL}(\pi\,\|\,\pi_{\text{ref}})$$

它有闭式解：

$$\pi^*(y|x)\;\propto\;\pi_{\text{ref}}(y|x)\,\exp\!\big(R(x,y)/\beta\big)$$

也就是把参考分布按奖励做指数倾斜。这个式子决定了 RL 能做什么、不能做什么：

  • 它只能重新分配已有的概率质量。$\pi_{\text{ref}}$ 给零概率的回答，乘以多大的系数仍然是零。所以 RL 主要是在 base model 的支撑集内锐化，覆盖率主要由预训练决定。
  • $\beta\to 0$ 时，质量全部集中到奖励最高的回答上。这就是 sharpening：pass@1 上升，多样性和大 k 下的覆盖率下降。
  • $R$ 只是代理目标。倾斜得越狠，越会放大 $R$ 本身的错误，也就是 reward hacking。KL 项的作用就是限制倾斜的程度。

不同算法只是逼近 $\pi^*$ 的不同方式：

方式代表
迭代地采样、打分、做梯度步PPO、GRPO
用偏好对直接拟合闭式解DPO
采 n 个只留好的，再做 SFTrejection sampling、RAFT
让老师直接给出目标分布on-policy distillation

第三层怎么用有限样本逼近

$\pi^*$ 没法直接采样，于是只能迭代：

$$\pi_{k+1}\;\propto\;\pi_k\,\exp\!\big(\hat A/\tau\big)$$

每一轮从当前策略采样，估计每个回答比平均好多少（advantage），据此把概率往好的方向挪一小步。这就是 mirror descent，Kimi k1.5 就是按这个框架写的。PPO 的 clip 和 TRPO 的 KL 约束都是在近似“挪一小步”。

照着这个式子实际去做，只会遇到三个根本困难，几乎每个算法改动都是在处理其中之一：

  1. 方差大（credit assignment）。一条几千 token 的回答只有一个标量奖励，估计非常吵。对策是减去 baseline，引入 critic 或 group mean，再做归一化。减 baseline 不引入偏差，因为 $\mathbb{E}[\nabla\log\pi]=0$。
  2. 数据不是当前策略采的（off-policy）。原因包括同一批数据更新多步、异步 rollout、推理引擎和训练引擎的数值不一致。要用这些数据就得乘 importance ratio，而 ratio 的方差会爆炸，所以才需要 clip、截断、masking，也就是 trust region。
  3. 奖励不可信，或者探索不够。代理奖励会被钻空子，所以需要 KL 约束、可靠的 verifier，以及不能被优化器利用的奖励形式。另外，策略只能强化自己采得到的东西，没采到的永远学不会。

小结：三个选择

  • 数据从哪来：on-policy 的程度有多高。
  • 每个样本给多大权重：奖励和 advantage 怎么算。
  • 每步走多远：trust region 怎么设。

上限由 base model 和奖励质量决定，算法主要决定能否稳定、高效地逼近这个上限。

问 2 · 这个视角能给成千上万的算法分类吗

三个选择不够，要扩成五个轴

不完全能。上面的三个选择只覆盖一大类算法：单轮生成、标量奖励、用 policy gradient 优化期望奖励。PPO、GRPO、DAPO、GSPO、CISPO、RLOO、REINFORCE++ 和各种 off-policy 修正都在这个框里，2025 年以来的大部分命名算法也属于这一类。

有五类放不进去，原因各不相同：

  1. 目标本身不是“期望奖励 + KL”。pass@k 训练优化的是 $\sum_x 1-(1-p_x)^k$，MaxRL 近似优化 $\sum_x\log p_x$，两者都不是期望奖励的指数倾斜。SPPO、Nash-MD 处理可能不传递的偏好，目标是一个博弈的 Nash 均衡。
  2. 奖励从哪来，本身是一个独立的设计轴。PRM、rubric/judge、self-certainty、熵最小化、TTRL 的多数投票、on-policy distillation 里老师的 log 概率，改的都是信号，不是估计量。把它塞进“怎么加权”粒度太粗。
  3. 不走 policy gradient 的估计路线。ILQL、soft Q-learning 这类 value-based 方法先学 Q 再导出策略；DPO 系直接拟合闭式解；RAFT、ReST 用过滤后的 SFT。它们和 PPO 逼近的可能是同一个目标分布，但估计方式完全不同。
  4. 多轮、有状态的 credit assignment。agent 任务里有环境状态和工具输出，turn-level advantage、GiGPO 的状态分组、环境 token 屏蔽，都是单轮 bandit 视角里不存在的维度。
  5. 采样分布的设计远不止 on/off-policy。选哪些 prompt（难度过滤、课程）、从哪个前缀分叉（TreeRL、在 entropy 高的位置分支）、用什么温度。

修正后的框架

  • 目标Objective逼近哪个分布或解。期望奖励、pass@k、log-likelihood、风险敏感目标；正则项（KL 方向、强度、参考策略固定还是滚动更新）；或者一个博弈均衡、一个老师分布。
  • 信号Signal奖励从哪来。规则 verifier、学习得到的 RM、PRM、judge/rubric、偏好对、内在信号、老师的 log 概率。
  • 数据Sampling样本怎么来。离线、在线或延迟；选哪些 prompt、怎么分叉、温度、过滤。
  • 估计量Estimator怎么把信号变成更新。policy gradient（baseline、归一化、credit 粒度、聚合方式）、闭式拟合（DPO 系）、过滤 SFT、value-based。
  • 更新控制Update control每步走多远。clip、IS 截断或屏蔽、近端 KL、每批数据更新几步。

判断

  • 作为分类器，五个轴大概能覆盖绝大多数方法。大部分论文只改一两个轴上的一个取值。真正新的工作是给某个轴增加一个新取值，比如把目标从标量奖励换成 Nash 均衡，或者把老师当作奖励来源。
  • 分类和“判断哪个改动重要”是两件事。分类告诉你一篇论文动了哪里；它重不重要，要看那一轴在实验条件下是否真的起作用。比如完全 on-policy 时，更新控制这一轴根本不生效（见问 3）。
  • “成千上万”这个说法我没有实证。要验证覆盖率，可以抽 100 篇左右近两年的 RL 论文逐一归类，看有多少放不进去、卡在哪一轴。这比凭印象下结论可靠。
问 3 · 从第一性原理看，这些算法真的有用吗

大部分改动决定不了结果，有用的多半是修正确性

一个算法到底能改变什么

base model、奖励、数据、算力都固定时，RL 算法能影响的只有梯度估计的偏差、方差和训练的稳定性。逐项看：

  • 大多数 clip 变体在 on-policy 时完全不起作用。每批数据只更新一步、并且 $\pi_{\text{old}}$ 在训练端重算时，$r=\pi_\theta/\pi_{\text{old}}\equiv 1$，clip 不会被触发：
    $$\nabla_\theta\,\min\!\big(r\hat A,\ \mathrm{clip}(r,1\!-\!\epsilon,1\!+\!\epsilon)\,\hat A\big)\Big|_{r=1}=\hat A\,\nabla_\theta\log\pi_\theta$$
    这时 PPO-clip、DAPO、GSPO、CISPO、SAPO 的梯度完全一样，都是 REINFORCE，区别只剩归一化方式。它们只在数据被复用、或数据来自旧策略时才有区别。
  • baseline 只降方差，不改变期望梯度。group mean、leave-one-out、critic 的差别在 $O(1/G)$ 量级，group 一大就基本消失。critic 只有在 $\lambda<1$、真正参与 credit assignment 时才会改变结果，而这时它也会引入偏差。
  • 归一化改的是目标，不是估计质量。对一个通过率为 $p$ 的 prompt，除以组内 std 相当于把目标从 $\sum_x p_x$ 换成 $\sum_x F(p_x)$，其中
    $$F'(p)=\frac{1}{\sqrt{p(1-p)}},\qquad F(p)=2\arcsin\sqrt{p}$$
    它给 $p$ 接近 0 或 1 的题更大的权重。这会影响 pass@k 和哪些题能被学会，但对 pass@1 的上限影响有限。
  • 任何算法都创造不出 base model 没有的概率质量。最优解是对参考分布的指数倾斜，上限从根上就不在算法里（见上面演示中的 y9）。

受控实验的结论和这几条推导一致：

  • ScaleRL 的 leave-one-out：从完整 recipe 里去掉任何一个组件，渐近上限都在噪声范围内。
  • GenAC 只换 advantage 估计量，GRPO、RLOO、PPO 的差距约 1 分。
  • DPO 系的各种 loss 在 β 调好之后打平。
  • PRM 加进奖励之后会被模型钻空子。

所以这些算法分三类

有用，而且必须

修正确性的

长 CoT 下用 $\lambda=1$、MoE 用 routing replay、消除训练与推理的数值不一致、多轮任务里屏蔽环境 token、限制同一批数据的复用次数。它们不提高上限，但不做的话训练会悄悄偏掉，或者直接崩溃。

有条件地有用

在系统约束下换效率和稳定性的

CISPO、GSPO、TIS、IcePop 只有在系统逼你 off-policy 时才起作用：异步 rollout、MoE、低精度推理、一批数据更新十几步。很多算法创新其实是对 infra 约束的回应，这是算法和 infra 之间最实质的联系。

大多是噪声

“新 loss 带来更高分数”的

增益通常是单 seed、只在 Qwen 上测的 1 到 3 分，落在评测噪声以内。不少是拿没调好的 baseline 比出来的。

真正的杠杆在哪

能显著改变结果的都在估计量之外：

  • 信号质量：verifier 的精度、奖励能不能被钻空子。奖励有偏差，目标分布就跟着偏。
  • base model 和数据：它们决定支撑集，也就是 RL 最多能锐化出什么。
  • 算力怎么花：batch size 和生成长度是少数在受控实验里明确抬高上限的因素。
  • 还没被证明、但原理上可能变得重要的两件事：长程 agent 的 credit assignment（horizon 越长，只靠最终结果的奖励越不够用）；探索（怎么让模型采到原本采不到的正确答案）。

两处需要打折

  • 现有证据很薄。多数是单 seed、单一模型族、1.5B 到 8B 规模。有些效应可能只在前沿规模才显现，而前沿实验室的内部消融不公开。比如 DeepSeek 说 Keep Routing “至关重要”，但没给数据。
  • “没用”指的是不决定上限，不是不值得做。第一、二类在工程上往往是必要的。

对 blog 的含义

与其逐轴给每个算法打分，不如直接论证上限在哪里决定、算法负责什么，再用上面三类改动作为骨架。
